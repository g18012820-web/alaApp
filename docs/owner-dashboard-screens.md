# شاشات لوحة تحكم المالك — النسخة الموسّعة

## 1. المسار (مُحدَّث)
الدخول للوحة المالك أصبح عبر **شاشة تسجيل الدخول نفسها**، وليس زرًا في صفحة الحساب (راجع `docs/owner-login-integration.md` للتفاصيل الكاملة):
```
شاشة تسجيل الدخول (بيانات المالك) → OwnerDashboardRoute
   ├─ إدارة الطلاب       → OwnerStudentsRoute
   ├─ إدارة الأساتذة      → OwnerTeachersRoute
   ├─ إدارة المواد        → OwnerSubjectsRoute
   │    └─ دورات المادة   → OwnerCoursesRoute
   │         └─ حصص الدورة → OwnerLessonsRoute
   └─ بيانات دخول المالك  → OwnerCredentialsRoute
```


## 2. مصدر البيانات
`OwnerContentRepository` (`lib/data/repository/owner/owner_content_repository.dart`) — مستودع محلي في الذاكرة (`ChangeNotifier` + Singleton)، **وليس متصلاً بأي خادم بعد** لأنه لا يوجد خادم حقيقي. كل الشاشات تقرأ/تكتب منه فقط، لذلك عند بناء الـ API الحقيقية (راجع `docs/phase-1-design.md`) يكفي استبدال هذه الفئة بتطبيق حقيقي (Retrofit) يتحدث مع الخادم، دون تعديل أي شاشة — لأن الواجهات تعتمد فقط على الدوال العامة (`addSubject`, `addCourse`, `addLesson`...) لا على التفاصيل الداخلية.

⚠️ **ملاحظة مهمة**: البيانات المُدخلة من هذه الشاشات تُفقد عند إعادة تشغيل التطبيق بالكامل من الصفر (لأنها في الذاكرة فقط، لا قاعدة بيانات محلية). إن كنت تريد أن تبقى البيانات محفوظة على الجهاز بين مرات التشغيل قبل جاهزية الخادم، أخبرني لأضيف تخزينًا محليًا (`floor`/SQLite الموجودة أصلاً في المشروع) كخطوة وسيطة.

## 3. المزايا المُنفَّذة
- **المواد**: إضافة / تعديل (اسم + وصف) / حذف (مع حذف تسلسلي لكل الدورات والحصص التابعة)
- **الدورات**: إضافة (عنوان، نبذة، سعر، سعر أصلي، اسم الأستاذ، شهادة إتمام)، تغيير الحالة مباشرة من القائمة (بيع مفعّل/متوقف/التسجيل مغلق/مخفية/مؤرشفة/محذوفة)، حذف
- **الحصص**: إضافة بأي نوع محتوى (فيديو/PDF/صورة/مقال/اختبار/ملف)، حقل رابط الفيديو يُستخدم مباشرة مع `UniversalVideoPlayer` من المرحلة 2 (اكتشاف تلقائي للمصدر)، تحديد مجانية/مقفلة، حذف
- عدّاد الدورات لكل مادة وعدّاد الحصص لكل دورة يتحدّثان تلقائيًا

## 5. القائمة الكاملة كما في ملف "05_Admin_Panel.md"
الشاشة الرئيسية للوحة المالك تعرض الآن **كل قسم مذكور في مواصفاتك** كعنصر قائمة — الأقسام الجاهزة تعمل فعليًا، والأقسام التي تتطلب خادمًا حقيقيًا (لأنها بيانات حيّة مثل الأرباح، استهلاك السيرفر، سجلات النشاط...) موسومة بوضوح "قريبًا — قيد الإنشاء" بدل عرض أرقام وهمية مزيّفة. هذا مقصود: عرض "0 أرباح" أو رقم عشوائي كأنه حقيقي يُعتبر تضليلًا، والأصح انتظار الخادم الفعلي.

الأقسام الموسومة "قريبًا" حاليًا: المحفظة والشحن، الأكواد، الاختبارات، الإشعارات المستهدفة، الجلسات النشطة، سجلات النشاط، الإحصائيات والرسوم البيانية، الإعدادات العامة للمنصة.

## 6. إدارة الطلاب والأساتذة (جديد)
- **الطلاب**: إنشاء/تعديل/حذف، حظر/فك حظر، إضافة أو خصم رصيد يدويًا (أزرار سريعة 500±)
- **الأساتذة**: ملفات تعريفية بلا حساب دخول (إنشاء/حذف)

⚠️ نفس ملاحظة التخزين المحلي في القسم 2 تنطبق عليهما أيضًا.

## 7. غير مُنفَّذ بعد ضمن هذه الشاشات
- تعديل الدورة/الحصة بالكامل (التنفيذ الحالي للتعديل جاهز فقط على مستوى المادة؛ تعديل الدورة/الحصة يحتاج نفس نمط `_openForm` لكن بحقل "existing" — يمكن إضافته سريعًا عند الطلب)
- رفع صورة/ملف فعلي (الحقول الحالية نصية لروابط لأن رفع ملفات حقيقي يحتاج تخزينًا سحابيًا حقيقيًا من القسم 4.2)
- إعادة ترتيب الحصص بالسحب (Drag & Drop)
- ربط "الأستاذ" بسجل مستقل قابل لإعادة الاستخدام بين عدة دورات (حاليًا يُنشأ سجل أستاذ جديد مع كل دورة)
