# وثيقة تصميم المرحلة 2 — المشغّل الاحترافي الموحّد
### (مبنية على القسم 4 و5 من ملف المواصفات)

## 1. البنية المعمارية

```
UniversalVideoPlayer (نقطة الدخول الوحيدة)
        │
        ├─ VideoSourceResolver.detect(url)  → يكتشف VideoSourceType تلقائيًا
        │
        ├─ NativePlaybackMode   → NativeVideoPlayerWidget   (video_player)
        ├─ EmbedPlaybackMode    → EmbedVideoPlayerWidget    (webview_flutter + iframe الرسمي)
        └─ ExternalPlaybackMode → ExternalOnlyVideoWidget    (url_launcher، فتح خارجي)
```

الاستخدام من أي مكان في التطبيق:
```dart
UniversalVideoPlayer(videoUrl: lesson.videoUrl)
```
ويمكن للمالك عند إضافة الحصة (إعدادات المصدر §4.7) **فرض نوع المصدر يدويًا** بدل الاعتماد على الاكتشاف التلقائي، عبر `forcedType:`.

## 2. جدول التغطية الفعلية لكل مصدر (بصراحة كاملة)

| المصدر | آلية التشغيل | ملاحظة |
|---|---|---|
| رفع مباشر / MP4 / WEBM / MOV / AVI / MKV | ▶️ مباشر (native) | عبر `video_player`، دعم كامل |
| HLS (M3U8) | ▶️ مباشر | دعم ممتاز على أندرويد و iOS |
| MPEG-DASH (MPD) | ▶️ مباشر | دعم جيد على أندرويد فقط بشكل موثوق حاليًا |
| RTMP | ▶️ مباشر (محاولة) | دعم غير مضمون خصوصًا على iOS — **يُنصح لاحقًا بالانتقال إلى `media_kit`** لتغطية 100% |
| Bunny/Cloudflare Stream, S3, GCS, Azure, Spaces, Wasabi, Backblaze, MinIO | ▶️ مباشر | لأن هذه الخدمات تُرجع رابط ملف/HLS مباشر |
| YouTube, Vimeo, Dailymotion, Facebook, Instagram, Twitch, Loom, Wistia | 🖼️ تضمين iframe رسمي | يعمل داخل التطبيق عبر WebView |
| Brightcove, JW Player, SproutVideo, Telegram | 🖼️ تضمين | يتطلب أن يزوّد المالك رابط iframe/embed الجاهز من لوحة كل خدمة عند إضافة الحصة |
| TikTok, X (Twitter) | 🖼️ تضمين جزئي | هذه المنصات تقيّد التضمين الرسمي المفتوح لأسباب سياسات خاصة بها؛ يُعرض عبر WebView لصفحة الفيديو نفسها كحل عملي |
| Google Drive, Dropbox, OneDrive, Box | 🖼️ تضمين | تحويل رابط المشاركة إلى رابط معاينة/تضمين تلقائيًا |
| MEGA, Terabox, pCloud | 🔗 فتح خارجي فقط | روابطها مشفّرة/مؤقتة من طرف العميل ولا توفر iframe رسمي موثوق — تُفتح في المتصفح بدل كسر التجربة داخل التطبيق |
| iframe / رابط مباشر عام | حسب النوع | fallback عام |

## 3. إعدادات لازمة قبل التشغيل الفعلي

1. `flutter pub get` لتنزيل `webview_flutter` و`url_launcher` المُضافتين إلى `pubspec.yaml`.
2. أندرويد: التأكد من صلاحية `<uses-permission android:name="android.permission.INTERNET"/>` في `AndroidManifest.xml` (موجودة عادة افتراضيًا في مشاريع Flutter).
3. iOS: إن استُخدمت روابط HTTP غير مشفّرة لأي مصدر، يلزم استثناء `NSAppTransportSecurity` في `Info.plist`.

## 5. اكتمال مزايا "المشغّل الاحترافي الموحّد" (القسم 5) — ما نُفّذ فعليًا الآن

| الميزة | الحالة | التفاصيل |
|---|---|---|
| واجهة موحّدة لكل المصادر | ✅ مكتمل | `UniversalVideoPlayer` |
| التحكم بالسرعة 0.5x → 2x | ✅ مكتمل | زر دوّار أعلى يسار المشغّل |
| استكمال المشاهدة من آخر نقطة توقف | ✅ مكتمل (محليًا) | `WatchProgressStore` عبر `shared_preferences`، يُزامَن مع الخادم عند بناء الـ API |
| نسبة تقدّم لكل حصة | ✅ مكتمل (محليًا) | تُحسب وتُحفظ تلقائيًا كل 5 ثوانٍ أثناء التشغيل |
| Watermark ديناميكي (اسم/بريد الطالب) | ✅ مكتمل | `watermarkText` — الشاشة المستدعية تمرّر اسم الطالب الحالي |
| منع لقطة الشاشة/تسجيل الشاشة | ✅ مكتمل على أندرويد | `FLAG_SECURE` عبر MethodChannel أصلي (`MainActivity.kt` + `ScreenSecurity`) — **غير ممكن تقنيًا على iOS** لعدم وجود واجهة برمجية عامة من آبل لمنع التسجيل فعليًا (أقصى الممكن هو الاكتشاف بعد وقوعه، غير مُنفَّذ بعد) |
| وضع الصوت فقط | ✅ تقريبي | يعتم الفيديو ويواصل الصوت؛ **لا** يبدّل لمسار بيانات أخف (يتطلب رابط صوت منفصل من الخادم) |
| جودة يدوية/تلقائية (HLS/DASH) | ⏳ مفتوح | `video_player` لا يعرض واجهة اختيار مسارات جودة برمجيًا بشكل موثوق عبر المنصتين؛ يتطلب `media_kit` أو ExoPlayer مخصص |
| روابط تشغيل موقّعة مؤقتة (Signed URLs) | ⏳ يتطلب خادمًا | الخادم يُصدر الرابط الموقّت عند طلب الحصة؛ المشغّل جاهز لاستقبال أي رابط كما هو |
| عرض المرفقات (PDF/صور) بجانب الفيديو | ⏳ المرحلة القادمة | يحتاج شاشة تفاصيل حصة كاملة، ضمن نطاق واجهات لوحة المالك/الطالب |
